## 1. 🔪 今日锐评
**物理痛点：端到端系统的“算力过载”与密集感知的资源冗余**。
自动驾驶全栈系统在 2024 年陷入了“BEV 特征图越大越好”的误区。UniAD 等架构虽然精度高，但因依赖全局密集 Occupancy 导致对计算资源的吞噬使其量产落地遥不可及。SparseDrive 的锐评点在于：它证明了 “世界不需要被填满，只需要被关键点观测”。它将传统的“先密集感知、再规控”的范式，重构为“以规控为核心的稀疏点查询”。通过仅保留 50 个用于路径搜索的稀疏 Query，将功耗和延迟降低了 70% 以上，实现了在 Orin-X 平台上 40 FPS 的极致闭环表现。这是 E2E 架构向工业普及转化的质变。

## 2. 🏗️ 模型架构 (Architecture Map)
- **Hierarchical Sparse Encoder**: 级散式采样，仅在 3D 参考点周围提取环视特征。
- **Shared Query Pool**: 感知与规划 Query 深度耦合，规划 Query 具备“自搜索”能力。
- **Symmetric Planning Head**: 输出多模态轨迹 [B, K, 6, 2]。
- **Tensor Shape 流**:
    - `Image Features`: [B, 6, C, H, W]
    - `Sparse Queries`: [B, 50, 256]
    - `Object Queries`: [B, 900, 256]

## 3. 💡 核心创新 (Math & Pseudo-code)
**双层稀疏交互（Bi-level Sparse Interaction）**:
```python
# PyTorch 风格伪代码
def forward_sparse_drive(self, img_feats, plan_queries):
    for layer in self.interaction_layers:
        # 1. Image-to-Query Sampling
        sampled_feats = self.grid_sampler(img_feats, plan_queries.pos)
        # 2. Ego-to-Agent Interaction (博弈建模)
        plan_queries = layer.self_attn(plan_queries, self.object_queries)
        # 3. Dynamic Refinement (逐层修正)
        plan_queries.pos += self.offset_head(plan_queries)
    return self.plan_head(plan_queries)
```

## 4. 📉 Loss 函数详解
- **L_plan**: Max-margin 轨迹分类损失。
- **L_aux_det**: 感知辅助监督损失。
- **L_safety**: 轨迹与 Query 间的最小物理距离惩罚。

## 5. 📊 关键指标 (SOTA Compare)

## 6. 📂 数据策略与预处理
- **Point-based Augmentation**: 针对稀疏查询点的采样偏移进行随机增强。
- **Multi-view Normalization**: 对齐不同相机的曝光度以稳定特征提取。

## 7. 🧩 时序与稳定性 (Temporal Stability)
- **Recursive Feature Cache**: 上一帧的 Query 锚点直接作为当前帧初始值，确保轨迹惯性。

## 8. ⚠️ 长尾与局限 (Corner Cases)
- **极小目标**: 稀疏 Query 采样率有限，对 50 米外的细杆状物存在漏检风险。
- **拓扑剧变**: 在剧烈颠簸场景下，稀疏点可能脱离特征区。

## 9. ⚖️ 优缺点总结
- **优点**: 推理延迟极低，功耗比高。
- **缺点**: 几何细节感知能力弱于密集 Occ 方案。
- **部署评分**: 9/10。

## 10. 🛠️ 落地建议 (Deployment)
- **算子合并**: 核心瓶颈在 grid_sample，建议使用单次 TensorRT DFA Plugin 调用。
- **量化**: 规划 Query 锚点必须保留 FP16 以防止坐标漂移。
