## 1. 🔪 今日锐评
**物理痛点：轨迹生成的“均值陷阱”、模式坍塌与确定性回归的逻辑短路**。
传统的端到端规划模型核心逻辑多基于 L1/L2 欧氏距离回归。在遇到“避让行人还是绕行”、“路口左右转皆可”等高度不确定的博弈场景时，回归模型往往会预测出一个“处于两个合法轨迹中间”的非物理路径（Mean Prediction）。这种“取平均值”的行为是导致自动驾驶车辆在复杂场景下产生“画龙”行驶、甚至直接撞向隔离带的物理诱因。DiffTraj 的锐评点在于：它彻底摒弃了回归范式，引入了生成扩散模型（Diffusion Models）。它将驾驶轨迹建模为一个复杂的连续概率分布，生成的路径既平滑又具备多样性（Multimodal），完美模拟了人类在博弈中的决策随机性。这标志着 E2E 规控从“做对题”向“有想象力”的物理跨越。

## 2. 🏗️ 模型架构 (Architecture Map)
- **Multi-modal Condition Encoder**: 提取 BEV 特征 [B, 256, 128, 128] 与历史轨迹。
- **Trajectory Diffusion Transformer (TDT)**: 12 层 Transformer 结构的噪声预测器。
- **Physical Score Refiner**: 在采样过程中注入物理梯度（Occupancy Gradient）。
- **Feature Flow & Shapes**:
    - `Latent Trajectory`: [B, 6, 2]
    - `Noise Level`: [B, 1]
    - `BEV Context`: [B, 512]

## 3. 💡 核心创新 (Math & Pseudo-code)
**得分引导轨迹采样 (Score-guided Trajectory Sampling)**:
利用反向 SDE 求解：dx = [f(x, t) - g^2(t) ∇x log pt(x|c)] dt。
```python
# PyTorch 风格伪代码
def sample_planning_trajectory(self, bev_feats, n_steps=50):
    # 1. Initialize from Gaussian Noise: [B, 6, 2]
    traj_t = torch.randn((B, 6, 2), device='cuda')
    # 2. Iterative Refinement
    for t in reversed(range(n_steps)):
        noise_pred = self.dit_model(traj_t, t, bev_feats)
        # 3. Apply Guidance (Constraint-driven)
        grad_occ = self.compute_collision_gradient(traj_t, self.occ_map)
        # 4. Langevin Update step
        traj_t = traj_t - alpha * noise_pred + beta * grad_occ
    return traj_t
```

## 4. 📉 Loss 函数详解
- **L_diff**: 得分匹配损失 (Score-matching)。
- **L_phys**: 物理一致性损失（曲率、加速度、SDF 碰撞）。
- **L_goal**: 目标点回归损失。

## 6. 📂 数据策略与预处理
- **Frenet Alignment**: 将轨迹投影至 Frenet 坐标系以解耦道路曲率。
- **Adversarial Noise**: 在训练阶段注入微小噪声，提高扩散模型的鲁棒性。

## 7. 🧩 时序与稳定性 (Temporal Stability)
- **Warm-start Sampling**: 利用 T-1 时刻的预测轨迹作为当前时刻扩散的初始化起始点，消除帧间抖动。

## 8. ⚠️ 长尾与局限 (Corner Cases)
- **实时性**: 生成式模型推理速度慢（~100ms），难以应对极高频闭环。
- **分布外 (OOD)**: 极端不规则轨迹的训练样本较少。

## 9. ⚖️ 优缺点总结
- **优点**: 决策具备极强的灵活性与物理平滑度。
- **缺点**: 推理步数多，显存占用大。
- **部署评分**: 3/10。

## 10. 🛠️ 落地建议 (Deployment)
- **加速**: 必须采用一致性蒸馏 (Consistency Distillation) 压缩采样步数至 4 步以内。
- **算子合并**: 在 GPU 上预计算静态 SDF 地图，避免逐点计算碰撞梯度。
