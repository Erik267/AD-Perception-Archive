## 1. 🔪 今日锐评
**物理痛点：拓扑逻辑断裂与通行性幻觉**。
传统的 3D Occupancy 方案（如 SurroundOcc, FB-OCC）本质上是在追求体素（Voxel）的几何重合度。在当前的工业方案中，感知模型往往只关注“格子是否填满”，而忽略了格子之间的“物理契约”。这导致在面对立交桥分层、长距离隔离带或狭窄施工通道时，模型往往会因为体素的不连续预测导致物理通行区域在逻辑上产生中断。这种“视觉对而逻辑错”的问题是导致端到端系统（E2E）在复杂路口产生“鬼刹”或“犹豫不前”的根本原因。TopoOcc 的锐评点在于：它将感知从单纯的“体积填充”提升到了“连通性审计”。它通过显式的拓扑约束，解决了规控系统（Planning）最担心的“感知结果不可导、不可搜索”的短路问题。在自动驾驶的下半场，如果感知不能输出具有物理意义的拓扑图，那么精度再高也只是“死”的体素。

## 2. 🏗️ 模型架构 (Architecture Map)
- **Image Encoder**: 采用 Swin-T + FPN 提取环视特征 [B, 6, 256, H/16, W/16]。
- **Voxel Lifting**: 利用 Cross-view Attention 将图像特征投影至 3D 空间，初始化体素特征池 V ∈ R^{B × C × X × Y × Z}。
- **Topology-Aware Head**: 
    - 引入 Graph Transformer 模块，将活跃体素重心视为 Graph 节点。
    - 预测邻接矩阵 A ∈ R^{N × N}，用于建模体素间的连通性。
- **Feature Flow & Shapes**:
    - `Input`: [B, 6, 3, 900, 1600]
    - `BEV Features`: [B, 256, 128, 128]
    - `3D Voxel Features`: [B, 256, 128, 128, 16]
    - `Topology Logits`: [B, N_nodes, K_neighbors]

## 3. 💡 核心创新 (Math & Pseudo-code)
**持久同调损失 (Persistent Homology Loss)**:
利用代数拓扑中的贝蒂数约束，确保生成的占用图在连通性上与真值一致。
```python
# PyTorch 风格伪代码
import torch
import torch.nn as nn

class TopoHead(nn.Module):
    def forward(self, voxel_feats):
        # 1. voxel_feats: [B, C, 128, 128, 16]
        B, C, X, Y, Z = voxel_feats.shape
        nodes = voxel_feats.permute(0, 2, 3, 4, 1).reshape(B, -1, C) # [B, N, C]
        
        # 2. Predict Connectivity (Edge Logits): [B, N, K]
        edge_logits = self.connectivity_mlp(nodes) 
        
        # 3. Graph Message Passing
        refined_nodes = self.gnn_layer(nodes, edge_logits) # [B, N, C]
        
        # 4. Final Occ Prediction
        occ_logits = self.occ_classifier(refined_nodes) # [B, N, N_classes]
        return occ_logits.reshape(B, X, Y, Z, -1), edge_logits
```

## 4. 📉 Loss 函数详解
- **L_geo**: Focal Loss + Dice Loss，用于基础体素占据预测。
- **L_topo_bce**: 监督邻接矩阵，权重 λ=2.0，防止桥梁分块断裂。
- **L_phys_consistency**: 物理一致性项，惩罚类别冲突的连通体素。
